# Покрокове налаштування для початківця

Ця інструкція доведе вас від нуля до того, що вакансії самі приходять у Telegram кожні 2 години.
**Усе тут безкоштовне.** Платний лише Claude, і він необов'язковий.

| Що | Навіщо | Ціна |
|---|---|---|
| Djinni (RSS) | джерело вакансій | безкоштовно |
| Gemini API, безкоштовний тариф *або* Ollama (локально) | «розумна» оцінка вакансій | безкоштовно |
| Telegram-бот | куди приходять вакансії | безкоштовно |
| Ваш Mac + launchd | автоматичний запуск | безкоштовно |
| Gmail + розсилки Work.ua / Robota.ua | ще два джерела (крок 9) | безкоштовно |

Займе приблизно 30–40 хвилин. Команди копіюйте повністю й вставляйте в Термінал.

---

## Крок 0. Відкрийте Термінал у папці проєкту

1. Натисніть `Cmd + Пробіл`, наберіть **Terminal** і натисніть Enter.
2. Вставте команду і натисніть Enter:

```bash
cd ~/Documents/work-search
```

Усі наступні команди виконуються в цьому вікні. Якщо ви закрили Термінал, спершу знову виконайте `cd ~/Documents/work-search`.

> Якщо на будь-якому кроці з'являється `command not found: uv`, встановіть uv однією командою
> `curl -LsSf https://astral.sh/uv/install.sh | sh` і перезапустіть Термінал.

## Крок 1. Перевірка, що все працює (без жодних ключів)

```bash
uv run jobradar --db data/test.sqlite3 run --dry-run --no-llm
```

Команда працює **близько 2 хвилин**, бо між запитами до Djinni витримує паузи, щоб нас не забанили.
Наприкінці ви побачите список вакансій і рядок на кшталт `{"collected": {"djinni": 197}, ...}`.
Отже, збір працює. Тут оцінка поки що «тупа», лише за ключовими словами. Це тестовий
прогін в окрему базу `data/test.sqlite3`, і на бойовий запуск він не впливає.

## Крок 2. Створіть файл із ключами `.env`

```bash
cp .env.example .env
open -e .env
```

Файл відкриється в TextEdit. Сюди на наступних кроках ви вписуватимете ключі.
Правило для цього файлу: `НАЗВА=значення`, **без пробілів і без лапок**. Після змін збережіть файл (`Cmd + S`).
Файл `.env` нікуди не завантажується, бо Git його ігнорує.

## Крок 3. «Мізки»: виберіть один варіант

### Варіант A (рекомендую): Gemini, безкоштовний тариф

У вас уже є ключ Gemini. Безкоштовний тариф дає змогу користуватися моделлю
`gemini-3.5-flash-lite` за $0. Ключ платним не стає, поки ви самі не підключите білінг.

1. Перевірте, що ключ на безкоштовному тарифі: відкрийте https://aistudio.google.com/apikey і
   подивіться тариф (plan/tier) біля ключа. Має бути **Free**. Якщо там платний тариф
   (Paid / Tier 1), створіть новий ключ у новому проєкті без білінгу
   (**Create API key** → **Create project**).
2. Впишіть у `.env` рядок (замість `...` вставте свій ключ):
   ```
   GEMINI_API_KEY=...
   ```
3. Перевірте:
   ```bash
   uv run jobradar llm-check
   ```
   Має з'явитися `provider: gemini`, оцінка тестової вакансії українською і `✅ OK`.

Що треба знати про безкоштовний тариф:
- Ліміти невеликі, а точні цифри Google показує на сторінці
  https://aistudio.google.com/rate-limit. Програма сама робить паузу 6 секунд між запитами.
  Якщо денний ліміт вичерпається, вакансії, які не встигли оцінити, просто почекають наступного запуску.
- На безкоштовному тарифі Google може використовувати запити для покращення своїх моделей.
  Це публічні вакансії й ваш профіль із публічного сайту, тож ризику мало. Але не вписуйте
  в `profile.yaml` нічого приватного.

### Варіант B: Ollama, повністю локально, без інтернету й без лімітів

Підходить, якщо не хочете віддавати дані Google. Мінуси: модель займає 3.4 ГБ на диску
(у вас вільно ~21 ГБ), працює повільніше (секунди або десятки секунд на вакансію) і трохи гірше
розуміє нюанси.

1. Завантажте й встановіть https://ollama.com/download (як звичайну програму), потім запустіть її.
2. Завантажте модель:
   ```bash
   ollama pull gemma3:4b
   ```
3. Відкрийте `config.yaml` (`open -e config.yaml`) і в розділі `scoring` замініть
   `provider: auto` на `provider: ollama`. Збережіть.
4. Перевірте: `uv run jobradar llm-check`. Має бути `provider: ollama` і `✅ OK`.

> Нічого з цього не хочете? Можна пропустити крок 3. Тоді працюватиме оцінка за ключовими словами.

## Крок 4. Telegram-бот

1. У Telegram знайдіть **@BotFather** (з синьою галочкою) і натисніть **Start**.
2. Надішліть `/newbot`.
3. Введіть назву, наприклад `Мій радар вакансій`.
4. Введіть username, який закінчується на `bot`, наприклад `pylyp_jobradar_bot`.
5. BotFather надішле **токен** вигляду `1234567890:AAH...`. Впишіть його в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=1234567890:AAH...
   ```
   Збережіть.
6. Відкрийте свого бота за посиланням від BotFather, натисніть **Start** і напишіть йому будь-що, наприклад «привіт».
7. У Терміналі:
   ```bash
   uv run jobradar tg-setup
   ```
   З'явиться рядок `TELEGRAM_CHAT_ID=123456789`. Скопіюйте його в `.env` і збережіть.
8. Перевірте:
   ```bash
   uv run jobradar tg-test
   ```
   У Telegram має прийти «✅ jobradar підключено».

Токен бота — це пароль, нікому його не показуйте.

## Крок 5. Перевірте свій профіль і фільтри

```bash
open -e profile.yaml
```

Це ваш профіль, який читає модель. Його складено з вашого резюме (`CV_Paster_master_2026_UA`)
і кейсів із paster.pro, без контактів. Що в ньому найважливіше:
- `preferences`: формат роботи (віддалено, Київ, інші міста України; без переїзду за кордон);
- `scoring_guidance`: правила оцінки простими словами. Наприклад, гемблінг дозволений, але
  отримує мінус ~15 балів. Сюди можна дописувати власні правила;
- `deal_breakers`: що для вас абсолютне «ні».

Якщо ви змінили профіль і хочете, щоб старі відсіяні вакансії оцінилися заново:

```bash
uv run jobradar requeue --skipped --rule-rejected
```

Вакансії, які вже надійшли в Telegram, повторно не надсилаються.

## Крок 6. Перший справжній запуск

```bash
uv run jobradar run
```

Займе 2–5 хвилин. Вакансії приходять у Telegram **по одній, щойно модель оцінила кожну**:
- 🟢 **80–100 балів**: варто відгукнутися;
- 🟡 **55–79 балів**: варто глянути.

У кожному повідомленні є назва-посилання, компанія, бал, чому підходить (✔), чого бракує (✖),
тривожні сигнали (⚠) і перше речення для супровідного листа (💡). Вакансії до 55 балів не надсилаються.

Під кожною вакансією є кнопки **✅ Відгукнувся** і **⏭ Пропустити**. Натискайте їх.
Програма збирає ці відповіді й поступово точніше вгадує, що вам підходить.

Наступні запуски надсилатимуть лише **нові** вакансії, без повторів.

## Крок 7. Автозапуск у хмарі (працює навіть із вимкненим ноутбуком)

Радар запускається на серверах GitHub (GitHub Actions, безкоштовно для публічного репозиторію).
**Будильник** — Google Apps Script: щогодини він просить GitHub запустити перевірку і, як сторож,
пише в Telegram, якщо запуски зупинилися. Схема та сама, що в shafa-watcher.

Що вже зроблено (вам нічого робити не треба):
- **Код запуску:** `.github/workflows/radar.yml`.
- **Секрети в GitHub:** ключ Gemini, токен бота, ID чату, ваш `profile.yaml` і ключ шифрування `STATE_KEY`.
- **Стан:** база (що вже бачили й надіслали) зберігається **зашифрованою** в гілці `state`.
  Ключ `STATE_KEY` лежить у вашому `.env`. Не губіть його: без нього стан не прочитати.
- **Автозапуск на Mac** вимкнено. Повний доступ до диска для bash більше не потрібен:
  Системні параметри → Приватність і безпека → Повний доступ до диска → вимкніть **bash**.

Що зробити вам (близько 10 хвилин, один раз):

**7.1. Токен GitHub для будильника**
1. Відкрийте https://github.com/settings/personal-access-tokens/new
2. **Token name:** `jobradar-trigger`. **Expiration:** 1 рік (за 14 днів до кінця бот нагадає).
3. **Repository access:** *Only select repositories* → `PhPaster/work-search`.
4. **Permissions → Repository permissions → Actions:** *Read and write*. Більше нічого не вмикайте.
5. **Generate token** і скопіюйте його (`github_pat_...`). Його показують лише один раз.

**7.2. Проєкт Apps Script**
1. Відкрийте https://script.google.com і натисніть **Новий проєкт**. Назвіть його `jobradar trigger`.
2. Видаліть усе у файлі `Code.gs` і вставте вміст файлу
   [`tools/trigger.gs`](tools/trigger.gs). Збережіть (`Cmd + S`).
3. Ліворуч натисніть ⚙ **Налаштування проєкту** → унизу **Властивості скрипта** → **Додати властивість**,
   три рядки:
   - `GH_TOKEN` = токен із кроку 7.1
   - `TG_TOKEN` = значення `TELEGRAM_BOT_TOKEN` з вашого `.env`
   - `TG_CHAT` = значення `TELEGRAM_CHAT_ID` з вашого `.env`

   Збережіть.
4. Поверніться в редактор (`<>` ліворуч). У випадному списку функцій праворуч від кнопки
   **Налагодження** виберіть **setup** (не будь-яку іншу) і натисніть **Запустити**.
   Google попросить дозволи: **Переглянути дозволи** → ваш акаунт → **Додатково** →
   **Перейти до jobradar trigger (небезпечно)** → **Дозволити**. «Небезпечно» тут лише тому,
   що скрипт ваш власний і Google його не перевіряв.
5. У тому самому списку виберіть **check** і натисніть **Запустити**. У журналі має бути `repository: 200`,
   а в Telegram прийде «🧪 тест сторожа».

Готово. Далі щогодини:
- GitHub перевіряє Djinni;
- нові відповідні вакансії оцінюються і приходять у Telegram;
- якщо щось зламалося, сторож напише ⚠️.

Усі запуски видно тут: https://github.com/PhPaster/work-search/actions. Запустити перевірку
вручну можна там само: **jobradar → Run workflow**.

Як автоматика береже безкоштовний ліміт Gemini:
- нові вакансії збираються щоразу, але до моделі йдуть лише ті, що пройшли фільтр назв
  (зазвичай кілька на день);
- не більше 150 запитів до Gemini на добу (`gemini.max_requests_per_day` у `config.yaml`).
  Решта вакансій чекає наступного дня, нічого не губиться;
- якщо Google сам скаже, що ліміт вичерпано, прийде повідомлення ⏸, і оцінка відновиться
  після 10:00 за Києвом (саме тоді Google скидає денний ліміт).

**Змінили профіль?** Після редагування `profile.yaml` оновіть секрет і переоцініть відсіяні вакансії:

```bash
gh secret set PROFILE_YAML < profile.yaml
```

Потім на сторінці Actions → **jobradar** → **Run workflow** поставте галочку **Re-score skipped…**
і натисніть **Run workflow**.

> **Не запускайте `jobradar run` на ноутбуці**, поки працює хмара: у локальної бази інша пам'ять,
> і вакансії прийдуть удруге. Подивитися статистику можна так: `scripts/state.sh pull`
> (завантажує хмарну базу), потім `uv run jobradar stats`.

## Крок 8. Корисні команди на щодень

Спершу завантажте свіжий хмарний стан: `scripts/state.sh pull`.

| Команда | Що показує |
|---|---|
| `uv run jobradar stats` | скільки вакансій знайдено, відсіяно, надіслано; скільки ✅/⏭; запити Gemini сьогодні |
| `uv run jobradar show` | останні оцінені вакансії з балами |
| `uv run jobradar show --status title_rejected` | що відсіяв фільтр назв (перевірити, чи нічого не загубив) |
| `uv run jobradar rescore 123` | переоцінити вакансію №123 і показати розбір |

## Крок 9 (необов'язково). Work.ua і Robota.ua через пошту

Ці два сайти блокують програми-збирачі, тому ми отримуємо вакансії з їхніх власних email-розсилок.

1. **Підпишіться на розсилки.** На work.ua і robota.ua увійдіть в акаунт, знайдіть
   «маркетинг директор» (а також «head of marketing», «бренд директор», «стратегічний директор», «CMO»)
   і натисніть **«Підписатися на вакансії» / «Отримувати нові вакансії на пошту»**.
2. **Створіть пароль застосунку Gmail.** Звичайний пароль не підійде.
   - Потрібна двофакторна автентифікація: https://myaccount.google.com/signinoptions/twosv
   - Відкрийте https://myaccount.google.com/apppasswords, назвіть пароль `jobradar` і скопіюйте 16 символів.
3. **Впишіть у `.env`:**
   ```
   IMAP_HOST=imap.gmail.com
   IMAP_USER=ваша.адреса@gmail.com
   IMAP_PASSWORD=16символівбезпробілів
   ```
4. **Увімкніть джерело.** У `config.yaml` в розділі `email_alerts` замініть `enabled: false` на `enabled: true`.
5. **Дочекайтеся перших листів-розсилок** (зазвичай за день) і запустіть `uv run jobradar run --sources email`.

⚠ Розбір листів я поки перевірив лише на зразках, які склав сам, бо справжніх листів ще не бачив.
Коли прийдуть перші справжні листи, покажіть мені результат: я підлаштую розбір під їхню верстку.
Пароль застосунку дає доступ до пошти. Він зберігається лише у вашому `.env` на ноутбуці, а програма
відкриває пошту тільки для читання.

## Якщо щось пішло не так

| Повідомлення | Що робити |
|---|---|
| `command not found: uv` | див. примітку в кроці 0 |
| `Gemini HTTP 400 ... API key not valid` | ключ скопійовано з пробілом або не повністю; перевірте `.env` |
| `Gemini quota exceeded` | вичерпано безкоштовний ліміт; решта оціниться при наступному запуску |
| `Ollama is not running` | запустіть програму Ollama (іконка ламки в рядку меню) |
| `model 'gemma3:4b' not found` | `ollama pull gemma3:4b` |
| `TELEGRAM_CHAT_ID is not set` | повторіть пункти 6–7 кроку 4 |
| `tg-setup` пише «No messages yet» | напишіть боту в Telegram ще раз і повторіть команду |
| Нічого не приходить у Telegram | `uv run jobradar stats`: можливо, нових вакансій просто немає |
